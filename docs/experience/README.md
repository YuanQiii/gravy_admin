# Experience library

> **曾名 `hermes/`** —— 2026-09-22 改名，理由是「目录名自解释、与 `docs/adr/` 同族（adr = 决策、experience = 经验）」。你或他人的记忆与旧链接里出现的 "hermes" 指的就是这里；改名的影响面见 [ADR 0017](../adr/0017-constraint-docs-single-routing-table.md) 补充说明。

本目录是 GVRAY 的**持久化经验库**，供人机共同引用。它现在是 `docs/` 的一个子层，与同层的 `docs/adr/`（决策）、上层语料 `.agents/project/`（规范）分工不同：**这里只装"过去时"的内容**——踩过什么坑、为什么最终这么定、哪些不变量虽能从源码读出来但值得写下来。当前状态与规则的描述不在这里（见维护约定第 5 条）。

## 内容

- `pitfalls/` —— 踩坑记录：已发生的问题、根因、规避动作。
- `patterns/` —— 工程模式：可复用不变量、深模块 / 薄适配器骨架。

> **「何时读」不在本文件维护**——路由表只有一个家，见 [AGENTS.md](../../AGENTS.md) 的「知识位置」与「按需阅读与同步更新」两节。本文件只描述"这库存什么"与维护约定。

> **已取消的桶**：原 `decisions/`（ADR 结论索引 + 变更决策摘要）已于 2026-09-22 取消。它的两块职责各有更权威的家——ADR 结论归 `docs/adr/` 目录本身（**不建索引**：索引是同一份映射的第二副本，必然漂移，实证见 ADR 0017 补充说明）；变更决策摘要归 `openspec/changes/archive/*/{proposal,design}.md`。

## 维护约定

1. **来源**：主要来自已归档的 OpenSpec 变更（`openspec/changes/archive/`）与 `docs/adr/`。变更归档后，把其中"值得记住"的踩坑 / 模式回填到这里。
2. **链接优先**：指向源码、ADR、变更文档的可点路径，不复制大段实现。
3. **一条只写一处**：发现重复先合并，不并存两份措辞不同的同一课。
4. **语言**：中文为主，保留英文专有名词与技术术语。
5. **不写**：可直接从 `AGENTS.md` / ADR / spec 读到的当前状态描述——只记「为什么 / 别踩 / 教训」。
6. **条目必须能退休**：一条经验被机制取代后（例如原本靠人记住的规则被 `.gitattributes`、lint 规则或测试覆盖），**删除该条并在提交信息里记一行"已由 X 取代"**。只增不减的库最后没人读。

## 内容来源

- `docs/adr/` 的全部决策记录（不在此处建索引）。
- 已归档的 OpenSpec 变更（`openspec/changes/archive/`）。
- 项目记忆中的硬约束 / 约定 / 教训。

> 不在此列"最近回填了哪几条"——那种清单每次回填就过期一次。要看现状就读 `pitfalls/` 与 `patterns/` 目录本身。

## 结构约定

当前是两个桶、三个文件。**这个规模不该拆成一坑一文件**（几十个小文件比一个 README 更难导航）：按「读的时机」分组（部署前 / 改 schema 前 / 新增端点前 / 排查失败时），单个 README 超过约 60 行再按主题拆分。
