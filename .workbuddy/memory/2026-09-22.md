## 调研「社区实践中文档体系应该长什么样」并为 GVRAY 做差距实测（只读，未改动任何文档）

### 证据来源

1. **本仓自有调研**（2026-09-11 产出，可直接引用）：`docs/ai-engineering-references.md`（12 个项目文件级扫描 + halo / dify / spec-kit 深挖）、`docs/ai-engineering-comparison-unibest.md`（与 unibest 逐项对照）。
2. **联网复核**（2026-09-22）：agents.md 标准与嵌套约定、Diátaxis 文档四象限与根级文件约定。

### 社区共识模型（六层）

| 层 | 社区做法要点 |
| --- | --- |
| 根级人向文件 | `README` / `LICENSE` / `CHANGELOG` / `CONTRIBUTING` / `SECURITY` / `CODE_OF_CONDUCT` —— **位置有硬约定**（GitHub、npm、semantic-release 会自动识别） |
| 指令层 | `AGENTS.md` 已是**开放标准**，2026 年中多数工具原生读（Codex CLI 原生支持根+嵌套、Cursor、Copilot、Cline、Zed、Amp）；Gemini CLI / Aider 走配置、Windsurf 走指针；Claude Code 用 `@AGENTS.md` 或 symlink 桥接。**甜点区 200–500 行**，2000 行的会挤占工作上下文 |
| 按需层 | **渐进式披露**：入口设基线，细节分文件且**文件之间互相引用**（如 `TYPESCRIPT.md` → `TESTING.md`），agent 逐层导航。monorepo 下**嵌套 `AGENTS.md`**：就近优先、**子文件只写 delta**、显式覆盖非静默、嵌套一般不超过一层 |
| 流程层 | skills 承载**本项目特有流程**（评审/测试/新增模块 SOP），不是第三方库 API 手册 —— 后者公开文档能查，前者查不到 |
| 事实与追溯层 | 规格驱动（openspec / spec-kit constitution）、ADR、经验库 |
| 门禁层 | CI 服务端强制；**"重新生成产物 + `git diff --exit-code`"** 让漂移当场失败（halo `openapi-check.yaml` 的现成实现） |

**人向文档的社区标准 = Diátaxis 四象限**：tutorial（学习）/ how-to（任务）/ reference（查阅）/ explanation（理解，**ADR 归此象限**）；其余文档进 `docs/` 按象限分目录，`docs/README.md` 作索引，跨文档用相对链接；目录小写连字符、文件名多用大写连字符。

### 三条被反复强调的铁律

1. **不要复制 README** —— README 是叙事（给人）、`AGENTS.md` 是祈使（给 agent），受众不同。复制粘贴是社区列出的头号错误。
2. **"唯一事实源"必须由物理手段保证**（import / symlink / 生成命令），靠"声明"的必然漂移 —— 与本仓 `comparison-unibest.md` §5.2 的结论完全一致，**社区与本仓调研独立得出同一结论**。
3. **门禁必须服务端**（本地钩子一条 `--no-verify` 就绕过）；且**指令文件要当生产配置**：CODEOWNERS 定所有权、只经 PR 修改、合并前用代表性任务实测、PR 描述里写清 before/after 行为变化。

### GVRAY 差距实测（2026-09-22 逐项核对）

**符合：** `AGENTS.md` **179 行**（落在 200–500 行甜点区内；但 11394 字符，中文密度高）· `CLAUDE.md` 一行 `@AGENTS.md` ✓（正是社区的 Claude Code 桥接做法）· 规格层（9 能力规格 + 38 归档）· 17 篇 ADR · `hermes/` 经验库 · 语料按任务路由的渐进式披露。

**偏离：**

| 缺什么 | 实测证据 |
| --- | --- |
| 嵌套 `AGENTS.md` | `Glob **/AGENTS.md` → **全仓仅根 1 个**；社区共识是 monorepo 根薄 + 每包一份 delta |
| CI 与 CODEOWNERS | `.github/` **不存在** → 无门禁、无所有权 |
| 根级人向文件 | 只有 `README.md` + `LICENSE`；**缺** `CHANGELOG.md` / `CONTRIBUTING.md` / `SECURITY.md` / `CODE_OF_CONDUCT.md` |
| `docs/` 按 Diátaxis 分象限 | 现为平铺：reference（configs/deployment/response-format）与 explanation（ai-*\*）与 how-to（api-testing）混装；**无 `docs/README.md` 索引** |
| 漂移检测接 CI | `scripts/check-docs.mjs` 已写好但未接 CI；halo 的 `openapi-check` 模式未平移 |

**结论**：GVRAY 的**事实与追溯层超出社区平均水平**（规格/ADR/经验库/语料路由，多数项目这几层是空的）；缺的是社区**最基础、最不需要设计能力**的两块 —— 根级人向文件与门禁层。**"缺的不是另一个体系，而是把已有规则接上 CI"**（此判断自 2026-09-11 起未变，今天仍成立且仍是同一个缺口）。
