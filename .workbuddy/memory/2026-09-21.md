"全靠推导"的真实代价不是推不出来，而是：① N 个读者 × M 次重复推导；② **结论因人而异且分歧不暴露**（两个 agent 各自推断出不同结论、都自认为对，冲突只在行为上显现）；③ **推断没有版本**（文档改了有 diff，推断改了没有任何记录）。

**所以完整机制是三段，不是两段**：**推导 → 审查 → 落到最便宜的可持久层**。第三段的"层"由可推导性光谱决定，而非默认写文档：
- 是规则 → 测试名 / 契约测试（自执行）
- 是意图 → 代码注释（随代码一起死）
- 是「刻意为之」的标记 → 代码内 inline 标记（最便宜）
- 是「否决过的方案」→ ADR（唯一能去的地方）
- 是「一个专题的已定基线」→ wayfinder 地图（本仓已有形态）

**四个必须加的约束**：
1. **只对档④⑤用** —— 人是最贵的验证器；对能 grep 的事 grill 人 = 烧注意力且让机制贬值。显式过滤条件：**推导不出高置信结论 ∧ 判错代价不对称 ∧ 之前没确认过**。
2. **问法不能引导，否则制造假事实** —— ⚠️ **`grilling` 技能"每问附推荐答案"的设计，在决策上推动收敛是好的，在事实确认上是危险的（诱导附和/顺从性偏差）**。事实确认要用**互斥假设择一 + 追问理由**：
   - ❌「这 5 个是刻意差异化的，对吗？」
   - ✅「我对这 5 个 controller 的守卫差异有两种自洽解释：A 刻意差异化（interface 决策）／B 迁移漏改。哪一个是当时的情况？为什么？」
   必须追问**理由**——理由才是能落盘的东西（ADR 要的正是理由 + 触发条件）。
3. **记录必须带失效条件 / 复核方式** —— 人的确认是**时间戳事实**（"截至 2026-09-21 这是刻意的"）。反直觉推论：**若一条确认能附上稳定的复核命令，它就降级了**——从档④（证不了）变档③（可查）。access.guard 那例附上"见 `access.guard.ts:35`"之后其实属于档③。**"能否给出复核方式"就是档④/档③的判据。**
4. **已确认的必须标「勿重开」，否则会被重新 grill** —— 没这个标记，下个会话会重新推导、重新推给同一个人，成本再付一次。

**一个诚实的限制**：这套机制**不解决"审查者的知识边界"**。若原写代码的人已不在、或问题太细，人只能答"不记得了"。那时只有两条路：接受不确定性并明确标注（"未确认，两种解释都自洽，改动前需评估"）——**"未知"必须被允许落盘**（wayfinder 的 `## Not yet specified` 正是此用）；或去查 `git log`/`blame` 找当时的提交与人。

**根因不是漏改，是复述**：同一条错我在同日早些时候已在 `AGENTS.md` 订正（批 2），但语料里那份没跟着改——**复述的那份不会随原始规则一起更新**。这印证了 ADR 0017 的「索引是同一份映射的第二个副本」论证，只是副本形态从"索引"扩到了"复述内容"。

→ 已确立为规范 7 并写入 ADR 0017 补充说明：**语料文档不得复述根文件的规则**。分工 = 根文件「一句话规则（自动加载，必须自足）」+ 语料「该规则的机制 / 字段 / 步骤」。
